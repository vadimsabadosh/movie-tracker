# Вимоги до застосунку movie-tracker

## 1. Опис

movie-tracker — REST API для ведення особистої історії перегляду фільмів. Центральна ідея: користувач позначає фільм як переглянутий і ставить власну оцінку; з накопиченої історії формується профіль вподобань, на основі якого застосунок рекомендує нові фільми.

## 2. Цільові користувачі

- Окрема людина, яка веде власну кінематографічну історію (одноко­ристувацький сценарій).
- Клієнти API: CLI, веб-фронтенд або скрипти. Фронтенд поза межами курсу.

## 3. Межі проєкту (out of scope)

- Автентифікація й багатокористувацький режим.
- Веб-інтерфейс.
- Інтеграція з зовнішніми API метаданих фільмів (TMDB) — можливе розширення, не базова вимога.
- Рекомендації на основі LLM — опціональне розширення за інтерфейсом `Recommender` (див. FR-7).

## 4. Функціональні вимоги

| ID | Вимога |
|----|--------|
| FR-1 | Керування каталогом фільмів: створення, читання, оновлення, видалення. Поля: назва, рік, жанри (один чи більше), режисер. |
| FR-2 | Позначення фільму як переглянутого з датою перегляду; скасування позначки. |
| FR-3 | Особиста оцінка від 1 до 10 та необов'язкова текстова нотатка до переглянутого фільму. |
| FR-4 | Історія переглядів з фільтрами (жанр, рік випуску, діапазон оцінок, період перегляду), сортуванням і пагінацією. |
| FR-5 | Пошук фільмів у каталозі за частиною назви. |
| FR-6 | Профіль вподобань: улюблені жанри та режисери, середня особиста оцінка за жанром. |
| FR-7 | Рекомендації: список непереглянутих фільмів каталогу, впорядкований за детермінованим скором на основі профілю вподобань (FR-6); кожна рекомендація містить пояснення. Рекомендатор реалізується за інтерфейсом `Recommender`, що дозволяє підставити інший алгоритм. |
| FR-8 | Статистика: кількість переглянутих фільмів, середня оцінка, розподіл за жанрами й роками. |

## 5. Нефункціональні вимоги

| ID | Категорія | Вимога |
|----|-----------|--------|
| NFR-1 | Продуктивність | p95 часу відповіді ≤ 200 мс на каталозі до 10 000 фільмів (локально). |
| NFR-2 | Коректність | Усі вхідні дані валідуються схемами Zod; помилки повертаються у єдиному форматі з відповідним HTTP-статусом. |
| NFR-3 | Безпека | Параметризовані SQL-запити; секрети й конфігурація середовища не зберігаються в репозиторії. |
| NFR-4 | Якість коду | TypeScript у режимі `strict`; ESLint і Prettier без помилок; покриття тестами ≥ 80 %. |
| NFR-5 | Детермінованість | Один і той самий стан БД дає однаковий результат рекомендацій (потрібно для відтворюваного порівняння harness у ПР № 7). |
| NFR-6 | Документація | OpenAPI-специфікація відповідає реальним ендпоінтам. |
| NFR-7 | Розгортання | Запуск локально однією командою; БД — файл SQLite, без зовнішніх сервісів. |

## 6. Технологічний стек

| Шар | Технологія | Обґрунтування |
|-----|------------|---------------|
| Мова | TypeScript (strict), Node.js LTS | Статична типізація допомагає агенту й компілятору ловити помилки. |
| HTTP | Fastify | Схеми валідації й генерація OpenAPI з коробки. |
| Дані | SQLite (better-sqlite3) | Безкоштовно, без окремого сервера, зручно для тестів. |
| Валідація | Zod | Єдине джерело правди для типів і схем. |
| Тести | Vitest | Швидкий, нативна підтримка TypeScript. |
| Якість | ESLint, Prettier | Автоматично перевіряні конвенції. |

## 7. Архітектура (початкове рішення)

Шарова структура: `routes` (HTTP) → `services` (бізнес-логіка) → `repositories` (доступ до SQLite). Логіка рекомендацій ізольована в модулі `recommendation` за інтерфейсом `Recommender`. Шари не звертаються до БД в обхід репозиторіїв.

## 8. Відповідність критеріям вибору застосунку

| Критерій | Оцінка |
|----------|--------|
| Чітка предметна область | Особистий облік фільмів; вузький набір функцій. |
| Поетапне нарощування за 7 робіт | Каталог → перегляди й оцінки → історія й фільтри → профіль → рекомендації → статистика. |
| Безкоштовний стек, сумісний з IDE | Так: Node.js, SQLite, Vitest. |
| Вимірювані критерії правильності | Детермінований скор рекомендацій, тести на фільтри й статистику. |
| Прийнятний ризик | Немає production-даних і реальних користувачів; БД — локальний файл. |
