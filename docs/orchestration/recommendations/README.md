Третя повна оркестрація Planner → Coder → Reviewer і друга з трьох для завершення застосунку (FR-6 → **FR-7** → FR-8). Результат: `GET /recommendations` за інтерфейсом `Recommender`; формулу зафіксовано як ADR-014.

## 2. Що знайшов Reviewer

| ID | Суть | Як вирішено |
|---|---|---|
| m1 | `round2` через `Math.round` округлює половини в бік +∞: малі від'ємні бали стають −0 і показуються як `(+0.00)`; −0.665 → −0.66, але 2.675 → 2.68 | Детерміновано (NFR-5), текст збігається зі значенням. Зміна була б W5 — не варта. Поведінку записано в ADR-014 (Рішення, Наслідки) |
| m2 | Не перевірено, що межі `limit=1` і `limit=100` приймаються | Залишено: поза планом тестування; той самий `PaginationQuery` вже перевірено на `/movies` |
| m3 | У `02-implementation.md` твердження «−0 лише при середній рівно 5.5» неточне | Handoff лишається дослівним за правилами skill; уточнення — тут і в ADR-014 |

## 3. Збереження контексту

- **Числа з плану пройшли наскрізь.** Planner розрахував очікувані скори фікстури вручну; людина обирала формулу за цими прикладами; Coder закріпив їх у тестах двох рівнів (чиста функція і HTTP); Reviewer перерахував їх незалежно — збіг до сотих.
- **Причина D6** (сортувати за показаним значенням, а не за прихованим float) дійшла до коду й до рев'ю: Reviewer прямо перевірив, що фільтр `score > 0` і схема `positive()` дивляться на те саме округлене значення.
- **ADR-003 «пояснення з тих самих складових»** реалізовано буквально: `explanation` будується з масиву `reasons`, який повертається поруч.
- **ADR-013 → FR-7:** чутливий до регістру збіг режисерів (зафіксований у FR-6) свідомо успадковано й протестовано («nolan» без причини).
- **Де контекст міг загубитися:** у handoff Coder неточно описав межу −0 (m3) — Reviewer виправив розуміння, але сам код від цього не залежав.

## 4. Події guardrails

- **W5:** два записи в `src/recommendation/` — кожен файл одним Write, обидва підтверджено людиною; після цього файли не змінювалися (Prettier їх не чіпав).
- W3, W4, B6 — без змін.
- Записи у vault (W6) — 2, підтверджено людиною; коміт (W2) — orchestrator.

## 5. Втручання людини

- Відповіді на Q1–Q4 (формула, фільтр `score > 0`, мова пояснення, ліміт).
- Два підтвердження W5, два — W6, коміт.

## 6. Спостереження

- План із розрахованими прикладами зробив доменне рішення (формулу) перевірюваним для людини: обирала не абстрактну формулу, а конкретний порядок фільмів.
- Planner заздалегідь звів W5 до двох запитів («кожен файл одним цілим записом») — guardrail лишився змістовним, а не шумом.
- Підміну алгоритму (вимога FR-7) доведено тестом зі stub-Recommender через `createServices`, без зміни `buildApp`.
