# Оркестрація: Movie posters via TMDB (FR-9)

П'ята повна оркестрація Planner → Coder → Reviewer і перша після курсу: застосунок тепер використовується по-справжньому (каталог з IMDb і веб-інтерфейс у `public/`, гілка `pr8`). Результат:
- `GET /movies/:id/poster`: постер шукається в TMDB за IMDb ID під час першого показу, шлях зберігається в БД, браузер отримує 302 на CDN TMDB;
- постери в каталозі, на сторінці фільму та в рекомендаціях;
- міграція 3 (`imdb_id`, `poster_path`);
- заповнення IMDb ID повторним запуском `npm run import:imdb`.

Без токена чи мережі застосунок працює повністю: замість постерів сірі заглушки (NFR-7).

## 3. Збереження контексту

- **Причини з плану дійшли до коду й рев'ю:**
  - збій TMDB не кешується (тест: після помилки наступний запит знову питає TMDB);
  - у БД зберігається шлях, а не URL;
  - сувора регулярка відсікає підозрілі шляхи для `<img src>`;
  - токен читається лише в `server.ts` і не потрапляє в повідомлення про помилки.
- **Де контекст загубився:**
  - У раунді 1 Coder обґрунтував `overflow: hidden` тим, що це «зберігає номери списку», а насправді воно їх ховало (U2). Причина записана, але не перевірена.
  - Тести не бачать результату в браузері: обидві UI-вади (U1, U2) пройшли `npm run check` і перше рев'ю. Їх знайшла лише ручна перевірка в Chrome. Висновок: для змін у `public/` перевірка в браузері має бути окремим кроком оркестрації, бо Coder і Reviewer не мають браузера.
- **Між оркестраціями:** план спирався на spec попередньої роботи (`docs/superpowers/specs/2026-11-13-imdb-import-and-web-ui-design.md`), де постери відкладено з приміткою «TMDB, schema change + ADR». Ця примітка дійшла до D11/D12.
