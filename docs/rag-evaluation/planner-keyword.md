# Plan: FR-8 Viewing Statistics (`GET /stats`)

## Goal
Add a read-only endpoint `GET /stats`. It returns the number of watched movies, the average rating, the distribution of watched movies by genre, and the distribution by release year. All figures are computed with aggregate SQL over `watches`, `movies`, `movie_genres` and `genres`. The code follows the layers in ADR-001: `StatsRepository` → `StatsService` → `/stats` route. It adds no migration and no dependency. Requirements: FR-8, NFR-1 (aggregation in SQL), NFR-3 (parameterized queries only), NFR-6 (full OpenAPI schema), NFR-2 (Zod schemas).

## Decisions
| # | Decision | Why | Rejected alternatives |
|---|---|---|---|
| 1 | The endpoint is `GET /stats`, with no query parameters in this version. | The vault names the `/stats` group (`Routes Layer`) and states no filters for FR-8. | `/stats/summary`, `/watches/stats`: not in the vault. Filter parameters: invented scope. |
| 2 | The response is `{ watchedCount, averageRating, byGenre: [{genre, count}], byYear: [{year, count}] }`. | The names match the FR-8 indicators. Arrays of objects are easier to extend than maps keyed by genre or year, and they keep a stable order. | Maps `{ "Drama": 3 }`: unordered, and key names are not a stable contract. |
| 3 | `averageRating` is a number rounded to 2 decimals in SQL (`ROUND(AVG(rating), 2)`). It is `null` when `watchedCount` is 0. | The average of an empty set is undefined, so `null` is honest. Returning 0 would be a false rating below the 1–10 range. A 404 or 409 on an empty history would be wrong, because "no watched movies yet" is a valid state. Rounding in SQL keeps the service free of float logic. Subject to Q1 and Q2. | `0` for an empty history: misleading. An unrounded float: noisy. |
| 4 | `byGenre` counts each watched movie once per genre. It is ordered by `count DESC, genre ASC`, where `genre` is the `genres.name_key` ordering. It returns `genres.name` for display. | A many-to-many relation means one watch counts toward every genre of its movie. The order is deterministic (NFR-5 style), which makes tests stable. Grouping by `g.id` avoids merging different genres. | Ordering only by count: ties are unstable. Counting by distinct genre string: unneeded because `name_key` is unique. |
| 5 | `byYear` counts watched movies by `movies.year` (the release year), ordered by `year ASC`. | FR-8 says "by years", and FR-4's year filter means release year (ADR-010). Ascending order reads as a timeline. | The year of `watched_at`: contradicts the FR-4 meaning of "year" without a vault statement. A fixed range filled with zeros: unneeded. Years with no watches are omitted. |
| 6 | There are three fixed-literal prepared statements: a summary (`COUNT(*)`, `AVG`), a genre `GROUP BY`, and a year `GROUP BY`. The service combines them. All three run in one `db.transaction` in the repository, via `this.db.transaction(...)`, so the figures come from one snapshot. | It meets NFR-1 and NFR-3, and the figures stay consistent with each other. With no input, there is nothing to bind. | A single query with `UNION`: unreadable. Aggregating in JavaScript: breaks NFR-1. |
| 7 | Responses are limited to genres or years that actually have watches. There is no `limit` and no pagination for the distributions. | The number of genres and years is naturally small, and the vault's `Pagination` applies to lists. | Paginated distributions: needless complexity. |
| 8 | There is no new ADR. If the human changes Q1–Q3, record an ADR with the `record-adr` skill after the Reviewer. | The public response shape (NFR-6) is a contract. ADR-010 sets the precedent that such contracts are recorded. | — |

Types come from `z.infer`. — files: `src/schemas/stats.ts` — done when: `npm run typecheck` is clean.
2. Create `src/repositories/stats-repository.ts` with `StatsRepository.summary(): ViewingStats`. SQL as fixed literals: `SELECT COUNT(*) AS watchedCount, ROUND(AVG(rating), 2) AS averageRating FROM watches`; `SELECT g.name AS genre, COUNT(*) AS count FROM watches w JOIN movie_genres mg ON mg.movie_id = w.movie_id JOIN genres g ON g.id = mg.genre_id GROUP BY g.id ORDER BY count DESC, g.name_key ASC`; `SELECT m.year AS year, COUNT(*) AS count FROM watches w JOIN movies m ON m.id = w.movie_id GROUP BY m.year ORDER BY m.year ASC`. Run them inside `this.db.transaction(...)`. No string interpolation. — files: `src/repositories/stats-repository.ts` — done when: the layer greps from the new-module skill print nothing.

## Test plan
| Case | Expected |
|---|---|
| Empty database | 200 with `{watchedCount: 0, averageRating: null, byGenre: [], byYear: []}`. |
| One watched movie (rating 8, year 1999, genres Drama and Sci-Fi) | `watchedCount` 1; `averageRating` 8; `byGenre` has both genres with count 1, ordered by name; `byYear` is `[{1999, 1}]`. |
| Several movies and ratings (for example 7, 8, 8) | `watchedCount` 3; the average is rounded to 2 decimals (7.67). |
| Genre counts exceed the total | The sum of `byGenre` counts is greater than `watchedCount` when a movie has several genres. |
| Genre ordering | `count DESC`, then genre name ascending on ties. |
| Year ordering | Ascending by year; several movies of one year are merged into one row. |
| Unwatched movies are ignored | Movies in the catalog without a `watches` row appear nowhere. |
| Cancelled watch (`DELETE /movies/:id/watch`) | The stats change: the count decreases and the movie leaves both distributions. |
| Rating update (`PUT`) | The average changes. |
| Genre names in different cases (for example `drama`, `Drama`) | Treated as one genre, because of `name_key` uniqueness. |
| OpenAPI | `/openapi.json` contains `/stats` with a 200 response schema. |
| Layer greps | Routes do not import `db` or repositories. Services do not import fastify or better-sqlite3. No built SQL strings in repositories. |
