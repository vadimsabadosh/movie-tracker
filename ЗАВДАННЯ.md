# ЗАВДАННЯ

## Застосунок

**movie-tracker** — REST API для ведення особистої історії перегляду фільмів. Користувач позначає фільм як переглянутий, ставить особисту оцінку й нотатку; на основі цієї історії застосунок будує профіль вподобань і рекомендує нові фільми з каталогу.

**Цільові користувачі:** окрема людина, яка хоче зберігати власну історію переглядів і отримувати персональні рекомендації (одноко­ристувацький сценарій, без автентифікації).

**Функціональні вимоги:**

1. Керування каталогом фільмів (створення, читання, оновлення, видалення).
2. Позначення фільму як переглянутого з датою перегляду.
3. Особиста оцінка (1–10) та текстова нотатка до переглянутого фільму.
4. Історія переглядів з фільтрами (жанр, рік, оцінка, період) і пагінацією.
5. Пошук фільмів за назвою.
6. Профіль вподобань: улюблені жанри та режисери, середня оцінка за жанром.
7. Детерміновані рекомендації непереглянутих фільмів із поясненням, чому фільм рекомендовано.
8. Статистика переглядів (кількість, середня оцінка, розподіл за жанрами й роками).

Детально: [docs/app-requirements.md](docs/app-requirements.md).

**Технологічний стек:** Node.js, TypeScript (strict), Fastify, SQLite (better-sqlite3), Zod, Vitest, ESLint, Prettier.

## Обрана агентна IDE

**Claude Code** — CLI та IDE-розширення. Підтримує MCP-сервери (конектор до бази знань, ПР № 3), hooks pre-/post-tool-use (guardrails, ПР № 4), кастомні skills (ПР № 5) та subagents (оркестрація, ПР № 6), а також виконання bash-команд і проєктні інструкції (`CLAUDE.md`).

## Мета harness

Прискорити й убезпечити розробку movie-tracker автономним агентом: дати агенту знання про архітектуру, конвенції й поточний стан застосунку (через окремий vault), формалізувати типові процедури розробки у вигляді skills та обмежити небезпечні дії за допомогою guardrails. Детально: [docs/harness-requirements.md](docs/harness-requirements.md).

## Цільові задачі агента

1. Генерація каркасу нового модуля (route → service → repository) за прийнятою архітектурою.
2. Генерація unit- та інтеграційних тестів (Vitest) для нової функціональності.
3. Рев'ю коду на відповідність конвенціям проєкту.
4. Підтримка технічної документації та OpenAPI-специфікації в синхронізації з кодом.
5. Аналіз причин збоїв тестів чи збірки (log triage) та пропозиція виправлень.
